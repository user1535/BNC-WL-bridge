로컬 브리지 사용 매뉴얼

기준: 2026-10-29. `bash scripts/run-server.sh` 후 http://127.0.0.1:8580/ 에서 시작합니다. 기본 세션은 results/prototype-risc0이며 이전 세션의 자산·미확인 거래를 덮어쓰지 않습니다.

연결

확장 없이 데모 지갑 연결을 누릅니다. 공개 Anvil 테스트 계정으로 브라우저가 서명합니다. 실제 자산이나 개인키를 사용하지 않습니다. 기존 웹페이지의 체인 상태·잔액은 5초마다 갱신됩니다. RPC 실패 시 이전 잔액을 최신으로 간주하지 마세요.

WorldLand에서 BNB로 보내기

1. WorldLand 탭에서 수량을 입력하고 거래 확인을 누릅니다.
2. 검토 패널의 지갑에서 승인 요청을 누르고 지갑에서 승인합니다.
3. 저장된 거래 상태 조회로 수락을 확인합니다. 이벤트 ID·블록이 자동 입력됩니다.
4. 증명 요청을 누릅니다. confirmation 2블록 확인 후 실제 RISC0 연산 증명을 만듭니다. 생성 중에는 기다리고 요청 상태를 확인합니다. 동일 요청은 중복 증명하지 않습니다.
5. 준비되면 패키지가 자동 수신됩니다. RISC0 SDK 재검증을 통과한 상태를 확인합니다. JSON 다운로드는 선택 사항입니다.
6. 패키지 목적지 화면으로 이동한 뒤 자산 청구 확인을 누릅니다.
7. 검토 패널에서 승인 요청 → 지갑 승인 → 저장된 거래 상태 조회를 진행합니다. BNB wrapped 잔액 증가를 확인합니다.

BNB에서 WorldLand로 반환

BNB 탭에서 wrapped 수량을 입력해 소각을 승인합니다. 거래 상태 조회 → 증명 요청 → 실제 RISC0 증명 생성·재검증 → WorldLand 목적지 화면 → 반환 청구 확인·승인 → 거래 상태 조회를 진행합니다. 원본 사용 가능 잔액이 복원되고 잠금이 감소합니다.

파일·이벤트·재개

증명 패키지를 JSON으로 저장하고 같은 세션에서 다시 불러올 수 있습니다. 파일 업로드 시 실제 SDK 검증을 다시 요청합니다. 증명이 누락되거나 변조되었거나 다른 guest/입력의 증명이면 청구를 진행하지 않습니다. 같은 이벤트를 다시 청구하면 거부됩니다.

내 전체 거래 이벤트 조회로 이전 lock/burn을 찾을 수 있습니다. 완료·미청구·확인 불가 상태를 구분합니다. 브라우저에 미확인 거래가 남아 있으면 새 서명보다 먼저 상태를 조회합니다. 자동 재전송은 하지 않습니다. Ctrl+C 후 동일 실행 명령으로 노드·계약·job 상태를 복구합니다.

신뢰·검증 범위

서버 운영자와 RPC를 신뢰합니다. 서버가 원본 root와 감사 기록을 등록할 수 있으며 사용자 자산 거래는 사용자가 직접 서명합니다. RISC0는 MPT·receipt·이벤트·금액·수신자·도메인 계산을 증명하고 서버 SDK에서 검증합니다. 목적지 컨트랙트는 MPT·이벤트·중복 청구를 검증합니다. composite proof 자체의 온체인 검증 및 원본 합의 인증은 하지 않습니다.

공개 감사

하단 공개 감사·전체 거래 기록에서 양쪽 체인의 이벤트·작업 기록과 감사 해시를 확인하거나 JSON으로 저장할 수 있습니다. 등록 root와 반복 조회한 원본 기록의 불일치가 확인되면 신규 증명 제공을 정지합니다. 이미 지급된 자산이 자동 취소되지는 않습니다.
